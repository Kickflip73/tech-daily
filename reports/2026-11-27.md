### 1. llm.asm — 17,252 行纯 x86-64 汇编写完三个 LLM 项目（⭐1,508，NEW，今日最猛新星）

> **仓库**：https://github.com/alesha-pro/llm.asm（2026-11-25 创建，2 天 1,508 星，217 forks）

**这是什么：** 三个完整 LLM 项目，**100% 纯 NASM 汇编**，零 C、零 libc、零运行时依赖，`nasm` 直接汇编 + `ld` 链接：

| 项目 | 二进制大小 | 亮点 |
|------|------|------|
| **01-qwen3-inference** | **14,712 B** | 静态 Linux ELF 跑 Qwen3-0.6B（Q8_0），内置 BPE 分词器、GQA/QK-Norm/RoPE/SwiGLU 全套手写汇编数学内核；**126.8 tok/s @ 40T，比 llama.cpp CPU 快 +18%~+36%**，与 PyTorch FP32 cosine 相似度 0.99965、64/64 token 精确匹配 |
| **02-baremetal-os** | **24,252 B** | **可裸机启动的 Qwen3-0.6B 操作系统**——Multiboot → Long Mode → AVX2/FMA/F16C → SMP → VGA+PS/2 多轮聊天；74-94ms 启动，0 GB 磁盘 |
| **03-minigpt-train** | **32,944 B** | 从零训练 Mini-GPT：寄存器分块 SGEMM、完整解析式反向传播（21 个梯度张量与 PyTorch cosine = 1.0000000000）、AdamW，TinyShakespeare 4 分钟 val_loss 4.19→1.51 |

**为什么是今日头牌：** 这是对"LLM 系统到底需要多少软件栈"的一次极限压力测试——答案是小到一个软盘都装得下（呼应前几日的 Tiny-2.1 DOS 语言模型，但那个是玩具，这个是**工程级碾压 llama.cpp 的正经性能**）。AVX2+FMA+F16C 手写 GEMM 在 CPU 上跑赢 llama.cpp（llama.cpp 是 C++ + 高度优化），说明**当前 CPU 推理栈仍有可观的汇编级余量**——这对"CPU 推理民主化"路线（openset-llm 等）是强信心信号。2026 年还在写汇编的人不是怀旧，是在证明 something。

**同生态位：** AMD 专属 llama.cpp fork 上 HN 267 分（见第二章）——本地推理性能优化是本周最强持续主题。

### 🔴 2. 1Password 安全事件更新（1,628 分，702 评论）

> **原文**：https://1password.com/blog/update-on-nov-2026-security-incident（SSL 抓取失败，以下基于 HN 讨论交叉验证，**待验证**）

**事实线（从引用官方邮件的评论还原）：**
1. 攻击者入侵一名员工的**企业 GitHub 账号**
2. 用该账号访问源码并**直接向生产环境后端服务推送恶意代码**（single-handedly ship to prod——无有效 code review 拦截）

4. 1Password 架构设计（vault 密钥在客户端，服务器端无法批量解密）限制了最坏情况——tptacek 评价："You were never going to be one SQL query away from vault plaintext at 1Password"

**为什么是本周最重要安全新闻：** 与 Check Point、US Treasury 同周的 "failure week" 收尾。"密码管理器自己被黑"是安全行业最讽刺的失效模式，但**真正的行业级教训是 GitHub 账号 → 生产部署这条供应链路径**：tptacek 指出这是"every SAAS breach 的标准 fact pattern"，且随员工数增长趋于必然。评论区同时炸出对 1Password 措辞的不满——官方邮件用 "As a courtesy..." 通报入侵，用户觉得被冒犯。

**行动含义（后端工程师视角）：** 检查自己团队的 GitHub branch protection 是否覆盖"admin 可绕过"路径、`dismiss stale approvals` 是否开启、agent 生成 PR 的自动合并链路是否有 human gate。
