### 2. ayghri/i-have-adhd — ADHD 友好的编码 Agent Skill（今日 ⭐+3,463）

> **仓库**：https://github.com/ayghri/i-have-adhd
> **语言**：Python

**这是什么：** 一个 Claude Code / Codex Skill，解决编码 Agent 的"信息埋没"问题——Agent 输出太长，关键结论被埋在中间，用户很难找到。

**核心设计：**
- **TL;DR 优先**：所有输出先给一句话结论，再展开细节
- **结构化分块**：用清晰的视觉分隔把长输出切分为可扫描的块
- **行动项高亮**：明确的下一步操作建议，不用用户在长篇输出中淘金

**技术信号：**
- 单日 +3,463⭐，增速仅次于 gods-eye-view，说明这是**普遍痛点**
- 不是新框架、不是新模型，而是一个**人机交互（HCI）层面的 Skill**——Agent 输出的"可读性工程"开始被认真对待
- 与昨日报告的 ReMe（Agent 记忆管理）和今日 llm_wiki（见下文）连成线：**Agent 基础设施正在从"能力"转向"体验"**

**对后端开发者的启示：** 如果你在做内部 AI 平台或 Agent 工具链，输出格式和交互设计的重要性不亚于模型能力。参考这个 Skill 的"结论先行"原则，改造你的 LLM 应用输出模板。

### 4. nashsu/llm_wiki — 增量式知识库构建（今日 ⭐+647）

> **仓库**：https://github.com/nashsu/llm_wiki
> **语言**：TypeScript

**这是什么：** 跨平台桌面应用，将文档自动转化为有组织、相互关联的知识库。与传统 RAG"每次都从零检索回答"不同，LLM 会**增量式构建和维护**一个持久化的 wiki。

**核心范式差异：**
| 传统 RAG | LLM Wiki |
|---------|---------|
| 每次查询独立检索 | 增量构建持久知识图谱 |
| 无状态，不积累 | 有状态，持续演化 |
| 答案质量依赖单次检索 | 知识库质量随时间提升 |

**技术信号：**
- 与昨日 ReMe（文件记忆系统）和今日 OpenViking（字节自进化上下文数据库）形成"Agent 记忆三剑客"
- 知识管理正在从"检索模式"转向"构建模式"——不是问什么查什么，而是让 AI 主动组织和维护知识结构

**对后端开发者的启示：** 如果你的内部知识库/RAG 系统回答质量不稳定，考虑引入"增量知识构建"层。与其每次重新检索，不如让 LLM 在后台持续整理和关联知识。

> 主题：博弈论 / 分布式计算 | 关键词：CFR、GPU 编译、80x 加速

反事实后悔最小化（CFR）是少数在 CPU 上比 GPU 更快的大规模数值工作负载之一。本文通过编译到 GPU 实现 **80 倍加速**，对博弈论 AI（如扑克、拍卖策略）和强化学习有重大意义。
