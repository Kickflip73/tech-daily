## 三、📄 arXiv 精选论文

### 🔬 AI / 大模型

**Programmable World Model — 可编程世界模型**（HuggingFace 79 ⭐）
> 主题：世界模型 | 关键词：状态持久化、可编程规则、视觉解耦

当前视频世界模型缺乏可靠的世界状态持久化与可编程规则约束。本文将**世界状态演化与视觉观察生成解耦**：Agent 把自然语言指令翻译为世界状态操作，再驱动视觉渲染。这是"世界模型作为可编程模拟器"的关键一步——对游戏引擎、机器人仿真、Agent 训练环境都有直接意义。

**Φ-Bench: LLM 能否工程化支撑自己的基础设施？**
> 主题：Agent 基准 / 自举 | 关键词：基础设施工程、全流程优化

不同于只测孤立 kernel 的旧基准，Φ-Bench 评估 LLM 端到端优化"为自己供能的基础设施"（推理引擎、算子库）的能力。**"AI 自举"（self-bootstrapping）从哲学话题变成可测量基准**。

**IdeaAMBIG: 研究想法规格中的实现关键缺口基准**
> 主题：Agent 科研 | 关键词：规格模糊性、实现差距

测量"研究 idea 描述 → 可执行实现"之间的关键信息缺口。与 PRAXIST、hexstellar、SAEScientist-Bench 连成一线：**AI 科研员的能力短板被逐项定位——"想法规格的完备性"是当前最大瓶颈之一**。

**Fortunate Recall: 面向 LLM 持久一致性的本体驱动记忆生命周期管理**
> 主题：Agent 记忆 | 关键词：记忆生命周期、本体、一致性

Agent 记忆管理从"存取"进入"生命周期治理"阶段：何时写入、何时更新、何时遗忘。与 GitHub 上 agent-memory（Markdown source of truth）路线互补——**记忆治理是长程 Agent 的下一个工程主战场**。

**ConvMem: 面向长上下文推理的卷积记忆**
> 主题：架构 | 关键词：卷积记忆、长上下文

用卷积式记忆机制替代纯注意力处理长上下文，与循环模型（前日报道）共同构成"Transformer 之外"的架构探索带。

**How Fragile Is Safety Alignment at Frontier Scale? 320B MoE 的单方向攻击**
> 主题：安全对齐 | 关键词：对齐脆弱性、单方向攻击、MoE

在 320B MoE 模型上用单方向（single-direction）攻击瓦解安全对齐。**前沿规模不等于对齐鲁棒性**——安全评测需要持续对抗性验证，而非一次性红队。

### 🤖 机器人 / 具身智能

**Show-Harness: 一个 VLM Agent 就能"扮演"机器人**（HuggingFace 122 ⭐）
> 主题：具身智能 | 关键词：VLM、语义动作接口、harness

## 五、🔍 趋势洞察与深度分析

### 趋势 1：跨平台框架的经济性根基被动摇

今日最值得后端架构师深思的是 **Shopify 回归原生**（716 分）与 **m3e-canvas 草图转代码**（5,881⭐）的同日对撞：

- 跨平台框架的存在理由是"一套代码省一半人力"。当 AI 生成双端原生代码的成本趋近于零，这个理由被釜底抽薪
- Shopify 作为 RN 最早、最大规模的采用者之一，其"回头"具有标志意义——不是 RN 技术不行，而是**成本结构变了**
- 延伸推论：所有以"降低人力成本"为核心卖点的抽象层（跨端框架、低代码、部分 ORM）都需要在 AI 时代重新证明自己

**给后端开发者的启示：** 技术选型评审的新问题："这个抽象层在 AI 辅助开发普及后还省什么？"省算力、省故障面、省认知负荷的抽象会存活；省人力的抽象会贬值。

### 趋势 2："AI 溯源基础设施"开始成型

三个独立信号在同一天出现：

- **TrajMark**（arXiv）：编码 Agent 工作轨迹的水印与篡改定位
- **Anthropic 威胁报告**新增"非法蒸馏"类目：模型输出的知识产权监测进入实战
- **数学界对 OpenAI 的信任质疑**（598 分）：未发表成果经手流程的信任危机

**给后端开发者的启示：** AI 时代的审计需求从"日志"升级为"可验证归因"——谁（哪个模型/哪个 Agent）在何时生成了什么、是否被篡改。做内部 AI 平台时，生成内容的元数据留痕与水印方案应从第一天就设计，事后补很难。

### 趋势 3：harness 决定论——从编码到机器人的同构

- 编码侧：Cognition SWE-2 专用模型 + codex-with-chatgpt 规划执行分离，**模型之外的执行框架成为竞争力核心**
- 机器人侧：Show-Harness 证明"VLM + 语义动作接口"即可操控机器人，harness 承担了把通用智能翻译为领域动作的全部工作
- 科研侧：PRAXIST、Avatar、hexstellar 本质上都是"LLM + 科研 harness"

**给后端开发者的启示：** "Agent 能力 = 模型 × harness"已成为跨领域共识。后端工程师在 harness 层（工具接口、状态管理、验证、恢复）的功力，恰好是这个公式里最稀缺的变量。

### 趋势 4：数据库分片的"产品化时刻"

PlanetScale Neki（分片 Postgres）的发布标志着：

- 分片技术从"大厂自建 + 开源框架"走向"云产品默认能力"——Vitess 八年运营经验的商品化
- Postgres 一统 OLTP 默认选型的趋势下，"分片即服务"补上了最后一块拼图
- Java 生态影响：JEP 544（AOT）+ Neki（透明分片）组合意味着"Java + 单库"的传统架构在弹性与扩展性上的两大短板同时被产业方案覆盖

**给后端开发者的启示：** 自建分库分表的维护成本 vs 云分片服务的费用，值得在下次容量规划时重新算账。同时 JEP 544 值得列入团队技术雷达。

### 趋势 5：AI 数学从"能力展示"进入"信任博弈"

- OpenAI Navier-Stokes Lean 证明（HN 125 分 + GitHub 1,715⭐）与 Anthropic 费马大定理仓库同榜
- 数学界的质疑（598 分）说明：**验证技术跑在信任机制前面**
- StochBench（Lean 随机过程基准）显示形式化方法正向概率领域扩展

**给后端开发者的启示：** 关键业务逻辑的"形式化轻量版"（不变式断言、 property-based testing、TLA+ 规格核心链路）是从这波浪潮里可以立刻借走的工具。
