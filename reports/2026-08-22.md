### 1. openai/codex — OpenAI 官方终端编码 Agent（今日 ⭐+4,159，总 ⭐111k）

> **仓库**：https://github.com/openai/codex
> **语言**：Rust | **协议**：Apache 2.0

**这是什么：** OpenAI 官方发布的轻量级终端编码 Agent。Rust 重写，性能优先，直接在命令行中执行代码生成、修改和调试任务。

**核心能力：**
- **本地优先**：完全在本地运行，代码不上传云端
- **多模式**：支持 `auto`（自动执行）、`ask`（先问后做）、`manual`（手动确认每步）三种交互模式
- **沙箱安全**：内置沙箱机制隔离 Agent 执行的代码
- **IDE 集成**：同时提供 VS Code / Cursor / Windsurf 插件版本
- **桌面应用**：`codex app` 启动独立桌面客户端
- **云端版本**：chatgpt.com/codex 提供云托管的 Codex Web

**技术架构（Rust 实现）：**
- 基于 Rust 的高性能 CLI 框架
- 与 OpenAI API 深度集成，支持 o3 / o4-mini / GPT-4.1 系列模型
- 文件系统监控 + 增量代码应用
- Git 集成：自动创建分支、提交、回滚

**后端开发者关注点：**
- Rust 实现意味着比 Python 方案更低的内存占用和更高的启动速度
- 作为 OpenAI 官方出品，Codex CLI 很可能成为终端编码 Agent 的事实标准
- 如果你在用 Claude Code，建议并行试用 Codex CLI 对比体验和输出质量
- 注意：当前主要面向 OpenAI 模型生态，对 Claude/Gemini 等第三方模型支持有限

### 2. stablyai/orca — 并行 Agent 舰队 ADE（今日 ⭐+724，总 ⭐50.7k）

> **仓库**：https://github.com/stablyai/orca
> **官网**：https://onOrca.dev
> **语言**：TypeScript | **协议**：MIT

**这是什么：** Orca 是首个专为"并行 Agent 舰队"设计的 **ADE（Agent Development Environment）**。类比传统 IDE 管理单个开发者，Orca 管理一整个 Agent 舰队。

**核心能力：**
- **多 Agent 并行**：同时运行 Claude Code、Codex、Cursor Agent、OpenCode 等多个 Agent
- **订阅隔离**：每个 Agent 使用你自己的订阅额度，不共享配额
- **跨平台**：Desktop（macOS/Windows/Linux）+ Mobile + VPS 三端覆盖
- **Workspace 管理**：统一追踪所有 Agent 的任务状态和代码变更
- **内置 Diff 审查**：不用离开 Orca 就能审查每个 Agent 的改动

**与 Superset 的对比：**
- Superset（昨日 Trending）侧重"并行执行 + 工作目录隔离"
- Orca 侧重"舰队管理 + 跨平台 + 订阅管理"
- 两者互补：Superset 管执行，Orca 管监控和调度

**后端开发者关注点：**
- 如果你需要同时用多个 Agent 处理不同模块（如一个写 API，一个写测试），Orca 是目前最完整的解决方案
- TypeScript 全栈实现，对前端友好的同时也有足够的扩展性
- 注意：当前仍处于快速迭代期，API 可能不稳定

### 3. diegosouzapw/OmniRoute — 免费 AI Gateway（今日 ⭐+768，总 ⭐52.7k）

> **仓库**：https://github.com/diegosouzapw/OmniRoute
> **官网**：https://omniroute.online
> **语言**：TypeScript | **协议**：MIT

**这是什么：** 一个免费的 AI Gateway，把 340 个 AI 提供商（含 90+ 免费层级）统一到一个 API 端点。支持 1200+ 模型。

**核心技术：**
- **统一端点**：一个 API Key 调用 Claude、GPT、Gemini、DeepSeek、GLM、MiniMax 等所有模型
- **配额感知自动降级**：当某个提供商额度用完，自动切换到下一个可用提供商
- **RTK + Caveman 压缩叠加**：平均节省 15-95% token（约 89%），永不触发速率限制
- **MCP / A2A 协议支持**：可直接接入 Claude Code、Cursor、Cline、Copilot
- **Desktop + PWA**：本地部署或浏览器使用
- **社区驱动**：450+ 贡献者

**免费额度：**
- 约 **15.3 亿免费 token/月** 通过叠加各提供商的免费层级
- 19 种路由策略（成本优先、速度优先、质量优先等）

**后端开发者关注点：**
- 如果你在做多模型应用或需要 failover 机制，这是目前最经济的方案
- RTK（推理时知识蒸馏）+ Caveman（token 压缩）的组合可以大幅降低 API 成本
- 注意：免费层级的稳定性不如付费，生产环境建议配置付费提供商作为 fallback

### 4. agent-substrate/substrate — Google 开源 Agent 高密度运行时（今日 ⭐+243，总 ⭐1.6k）

> **仓库**：https://github.com/agent-substrate/substrate
> **语言**：Go | **协议**：Apache 2.0

**这是什么：** Google 开源的 Agent 高密度运行时环境，专为大规模 Agent 部署设计。⚠️ **非 Google 官方产品**，但代码质量有 Google 风格。

**核心技术：**
- **亚秒级 Agent 恢复/挂起**：sub-second resume/suspend 操作
- **高密度多路复用**：在相同计算基础设施上重度多路复用多个 Agent
- **多沙箱技术**：支持 microVM（Firecracker）和 gVisor 两种隔离方案
- **控制平面**：完整的 Agent 生命周期管理（创建、调度、暂停、恢复、销毁）
- **Go 实现**：利用 Go 的 goroutine 和 channel 实现高效并发

**后端开发者关注点：**
- 这是目前唯一一个从"大规模 Agent 部署"角度设计的运行时，不是又一个 Agent 框架
- 如果你在构建企业级 Agent 平台（需要同时运行数千个 Agent），这是值得深入研究的底层基础设施
- microVM + gVisor 的双隔离方案在安全性和性能之间提供了灵活选择
- 项目还很新（1.6k ⭐），但架构设计体现了 Google 级别的工程思维

### 🟡 MemTrapBench: LLM 记忆使用中的认知陷阱基准测试（HF ⭐+29）

## 四、🔍 趋势洞察与深度分析

### 趋势 1：Agent 运行时进入"分层架构"时代

今天的 Trending 清晰地展示了一个分层架构正在形成：

| 层级 | 代表项目 | 职责 |
|------|----------|------|
| **应用层** | openai/codex, Claude Code | 终端用户直接交互的编码 Agent |
| **编排层** | stablyai/orca, superset-sh/superset | 管理多 Agent 并行和任务分配 |
| **网关层** | diegosouzapw/OmniRoute | 统一 API 接入、负载均衡、成本控制 |
| **运行时层** | agent-substrate/substrate | 高密度 Agent 沙箱和生命周期管理 |
| **优化层** | affaan-m/ECC, caveman | Token 压缩、性能优化、技能增强 |

**给后端开发者的启示：**
- 不要只关注应用层（Codex/Claude Code），运行时层和网关层才是构建企业级 Agent 平台的关键
- 如果你的团队需要同时运行 100+ 个 Agent，substrate 的 microVM/gVisor 隔离方案值得研究
- OmniRoute 的"叠加免费额度"思路是降低 AI 成本的有效策略
