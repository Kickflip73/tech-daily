> **仓库**：https://github.com/deepseek-ai/deepseek-harness

- **模块化目录**：`apps/`（应用层）、`packages/`（核心包）、`native/`（原生层）、`examples/`（示例）、`docs/`（文档）

**当前状态：** Developer Preview 阶段，明确声明 **会有破坏性变更**。已获 8,828 forks，迭代极快。

**安装即用：** `npx @deepseek-ai/dsh web`，Web UI 默认 3080 端口。社区通过 Discord 和 GitHub Discussions 活跃交流。

**后端开发者关注点：**

### 2. watermarks-remover — AI 溯源水印清除工具（⭐ 8,122）

> **仓库**：https://github.com/guillaumemeyer/watermarks-remover
> **版本**：v0.5.0 | **语言**：Python 3.10+ stdlib | **协议**：MIT

**这是什么：** Agent Skill + 纯 Python 服务，清除多厂商 AI 溯源标记。核心卖点是 **零依赖**（纯 Python stdlib），单脚本即可运行，也可启动 HTTP 服务。

**三层清除架构：**

| 层级 | 目标 | 方式 |
|------|------|------|
| **Layer A** | 隐形 Unicode、exotic spaces、bidi、tag chars | 确定性 Python 脚本 |
| **Layer B** | 统计性（token-sampling）文本水印 | Agent 重写 + 可选 rewrite hook |
| **文件层** | C2PA / EXIF / XMP / doc props | PNG、JPEG、WebP、SVG、PDF、DOCX、ODT、HTML、Markdown |

**支持的厂商/生态：** Claude、Gemini / SynthID-Text、OpenAI 溯源、开源 LLM Kirchenbauer 风格标记。

**部署方式：**
- **纯 Python 3.10+ stdlib**：零依赖，单脚本运行
- **HTTP 服务**：`python3 service/scripts/server.py --host 127.0.0.1 --port 8765`，提供 OpenAPI 3.0.3 接口
- **Docker**：核心镜像 + MarkLLM / MarkDiffusion / CtrlRegen 可选扩展镜像
- **Agent Skill**：支持 Grok、Claude 等 Agent 直接调用（`/remove-ai-marks`）

**后端开发者关注点：**
- 如果你在处理 AI 生成内容的合规或隐私场景，这个工具提供了系统性的清除方案
- HTTP 服务设计干净，可作为微服务接入现有 Pipeline
- 可选工具链：c2patool（C2PA inspect）、exiftool（元数据清洗）、qpdf（PDF 结构重建）
- 注意伦理边界：工具明确声明"仅用于你拥有所有权的内容"

### 3. mole — 带预算控制的深度研究 Agent（Go，HN Show）

> **仓库**：https://github.com/lajosdeme/mole
> **语言**：Go 1.25+ | **协议**：未明确

**这是什么：** 终端运行的深度研究 Agent，解决三个核心问题：
1. **预算失控** — 每次模型调用前预留预算、后结算，数据库 Schema 层保证非负约束（实测 overshoot 0%）
2. **引用不可信** — 每个 claim 必须携带原文引用，且逐字验证，不匹配的 claim 直接丢弃
3. **本地数据泄露** — 本地 CSV/文件夹分析时，模型只能看到聚合结果（计数、均值、test results、buckets），原始数据不出境

**工作流程：** 分解问题 → 搜索（Tavily/Brave）→ 阅读源 → 提取 claim → 逐字验证引用 → 发现矛盾 → 生成带引用的答案

**技术亮点：**
- **单静态二进制**，CGO_ENABLED=0，零运行时依赖
- **SQLite 数据库**，XDG 数据目录，自动创建
- **MCP 协议支持**：`mole serve` 启动 MCP Server，Unix socket 模式 0600
- **双重模式**：完整研究模式（mole 做全部推理）和 toolkit 模式（外部模型做推理，mole 提供搜索/验证能力）
- **本地数据隐私**：模型选假设模板 + 列名，mole 渲染 SQL 执行，只返回聚合结果。`mole crossings <session-id>` 可精确查看哪些数据离开了本机
- **数据集模式**：`--mode dataset` 可输出结构化数据（CSV/JSON），支持模糊行合并
- **Follow-up**：`mole ask <session-id>` 基于已有 claims 回答后续问题，不花额外搜索费用
- **多平台安装**：curl 脚本、Homebrew、AUR、deb/rpm、go install 全覆盖

**后端开发者关注点：**
- Go 写 Agent 工具性能极佳，单二进制分发体验极好
- 预算控制的数据库 Schema 层设计（非负约束）值得借鉴
- MCP 集成让工具可被任何支持 MCP 的 Agent 调用，这是正确的开放策略
- 本地数据分析的隐私保护设计（模型不写 SQL，只选模板）是正确的零信任思路

### 4. agent-safe-pipeline — Agent 安全授权参考架构（⭐ 373）

> **仓库**：https://github.com/decionis/agent-safe-pipeline
> **文档**：https://decionis.com/docs
> **语言**：TypeScript | **协议**：Apache 2.0

**这是什么：** AI Agent 安全授权的参考架构。核心思想：Agent 可以**提议**动作，但**不能授权**执行。由 [Decionis](https://decionis.com/) 公司出品。

**四阶段安全流水线：**
1. **Immutable Intent Capture** — 不可变意图捕获（Agent 提出操作请求）
2. **Decionis Policy Verdict** — 独立策略裁决（ALLOW / ESCALATE / BLOCK）
3. **Verified Human Approval** — 人工审核确认
4. **SafeExecutor** — 一次性意图绑定授权执行

**技术标签：** Policy-as-Code、MCP、Human-in-the-loop、AI Governance、Authorization、agentic-ai

**后端开发者关注点：**
- Agent 越能干，安全风险越大。这个架构提供了"提议-裁决-审批-执行"的安全闭环
- 如果你的 Agent 可以操作生产环境（数据库、K8s、部署），强烈建议参考这个模式
- Policy-as-Code 让安全策略可版本控制、可审计
- 与 MCP 集成，可被任何支持 MCP 的 Agent 调用
