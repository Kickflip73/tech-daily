### 1. tt-a1i/archify — Agent 架构可视化技能（今日 ⭐+3,722）

> **仓库**：https://github.com/tt-a1i/archify
> **语言**：JavaScript | **协议**：MIT

**这是什么：** 专为 AI Agent 设计的「架构可视化技能包」，让 Agent 能自动生成精美的架构图、工作流图、时序图、数据流图和生命周期图。输出为自包含的 HTML，支持动画和高质量导出。

**技术架构：**
- **纯前端渲染**：基于 Web 的 SVG/Canvas 渲染引擎，无需后端依赖
- **自包含 HTML**：单文件输出，内含所有样式和交互逻辑，可直接嵌入文档或邮件
- **动画支持**：状态流转、数据流动态展示
- **Crisp 导出**：支持高分辨率 PNG/SVG 导出，适合技术文档和演示

**核心洞察：** 这不是又一个 Mermaid 替代品，而是「Agent-native」的——Agent 读取代码库后，自动调用此技能生成对应架构图。它与 Claude Code、Cursor、Codex 等 Coding Agent 深度集成，把「理解代码 → 画架构图」的链路完全自动化。

**后端开发者关注点：** 如果你在做复杂微服务系统或事件驱动架构，让 Agent 自动产出架构图比手写 PlantUML 高效 10 倍。HTML 自包含格式意味着可以直接塞进 KM 文档或 Confluence。

### 4. tailscale/tailcat — 去中心化 netcat（今日 ⭐+841）

> **仓库**：https://github.com/tailscale/tailcat
> **语言**：Go | **母公司**：Tailscale

**这是什么：** 像 netcat，但通过 Tailscale 的数据平面传输，**不需要 Tailscale 的控制平面**。意味着你可以在两台已经通过 Tailscale 联网的机器之间直接建立管道，无需登录、无需 ACL 配置、无需控制服务器。

**技术细节：**
- **WireGuard 直连**：基于 Tailscale 已建立的 WireGuard 隧道
- **零控制平面依赖**：不调用 Tailscale API、不检查 ACL、不经过 DERP relay（除非 NAT 穿透需要）
- **标准 I/O 管道**：完全兼容 netcat 的使用习惯，`echo "hello" | tailcat peer:port`
- **Go 实现**：单二进制文件，交叉编译到所有平台

**工作原理：** 一侧运行 tailcat server（监听器）获得短连接 token，另一侧用该 token 连接 client。所有流量通过 WireGuard 端到端加密，初始连接经 DERP 服务器引导，随后 magicsock 执行 NAT 穿透升级到直连。

**后端开发者关注点：** 这是一个非常有意思的信号——Tailscale 正在把「连接层」从「控制层」彻底解耦。对于需要内网穿透但不想依赖第三方控制服务的场景（如边缘计算、IoT 设备），tailcat 提供了最小权限的连接方案。

### 5. workweave/router — Agentic 模型路由网关（今日 ⭐+464）

> **仓库**：https://github.com/workweave/router
> **语言**：Go

**这是什么：** 专为 Agent 系统设计的模型路由网关。每个 Prompt 在 <50ms 内路由到最合适的模型，仅通过更换一个 endpoint 即可降低 40-70% 的推理成本。

**核心技术：**
- **智能路由策略**：基于 Prompt 内容、历史延迟、成本预算、模型能力图谱做动态决策
- **亚 50ms 决策**：本地规则引擎 + 轻量模型分类器，无需额外 LLM 调用
- **Failover 与降级**：主模型不可用时自动切换备用模型
- **成本追踪**：按请求维度统计各模型调用量和费用
- **Go 实现**：高性能、低内存、易部署为 sidecar

**本质洞察：** 这是 Agentic 系统的「负载均衡器」。当系统同时对接 Claude、GPT、Gemini、本地模型时，路由层决定了成本和体验的天花板。workweave/router 填补了开源生态中「轻量级模型路由」的空白，对比 Kong/Gloo 的 AI Gateway，它更专注、更快、更轻。

**后端开发者关注点：** 如果你在运行多模型 Agent 系统，路由层是刚需。Elastic License（源码可用，商用需授权），部署前确认授权条款。

> **HN 讨论**：https://news.ycombinator.com/item?id=49499854

**核心教训：**「有观点的」系统配置需要经过严格的安全审计，否则「便利性」会成为攻击者的便利。

### [cs.CV] UrbanGround: From Local Perception to Spatial Agency in a Real-Scale City
> **链接**：https://arxiv.org/abs/2608.27456v1
> **作者**：Tianjie Ju, Zheng Wu, Yueqing Sun 等

多模态大语言模型（MLLM）可以解释街景图像，但城市智能体（urban agent）的关键在于：当智能体开始移动后，局部感知的信息是否仍然有用。本文研究了当前 MLLM 智能体在真实规模城市环境中将局部城市感知转化为可靠行动的能力边界。对自动驾驶和机器人导航有参考价值。

### [cs.CL] CritICL: Inference-Time Weak-to-Strong Generalization from Small Language Model Failure Modes
> **链接**：https://arxiv.org/abs/2608.27455v1
> **作者**：Yufan Wu, Yinghui He, Zhengyi Hu

推理时扩展（inference-time scaling）显著提升了 LLM 的推理性能，但这些方法通常依赖重复生成或外部验证器。本文提出 CritICL：利用小语言模型的失败模式，在推理时实现弱到强的泛化。核心思路是让小模型先尝试，分析其失败模式，然后指导大模型规避这些陷阱。

- **tailcat**（+841⭐）— 去中心化网络连接，零控制平面

**给后端开发者的启示：** 你的 AI 系统中，哪些环节还是「单点依赖」？网络连接、模型推理、数据存储——每个环节都值得思考去中心化 + 智能路由的可能性。
