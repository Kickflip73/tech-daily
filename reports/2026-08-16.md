### 1. deepseek-ai/deepseek-harness — 万物皆插件的 AI Agent 运行时（⭐115,168，今日趋势绝对霸主）

> **仓库**：https://github.com/deepseek-ai/deepseek-harness
> **语言**：TypeScript | **协议**：MIT

**这是什么：** DeepSeek 开源的通用 AI Agent 运行时框架，核心理念是"Everything is a Plugin"，将 Agent 能力完全插件化。

**技术架构：**

**生态爆发：** 该仓库 8 月 13 日创建，仅 3 天即突破 11.5 万星，并催生了 10+ 个生态子项目（awesome-dsh-plugin、dsh-web-ui、dsh-TUI 等），形成完整的"DeepSeek Harness 生态"。

**后端开发者关注点：** 这是目前 Agent 运行时领域最热的开源项目。如果你想构建自己的 Agent 平台，"插件化 + 编排引擎"的架构思路值得深入研究。与 OpenSandbox（阿里）的路径不同——DSH 更偏"前端+编排"，OpenSandbox 更偏"沙箱+安全隔离"。

### 6. decionis/agent-safe-pipeline — AI Agent 安全执行参考架构（⭐442）

> **仓库**：https://github.com/decionis/agent-safe-pipeline
> **语言**：TypeScript | **协议**：Apache 2.0

**这是什么：** AI Agent 安全执行的参考架构——Agent 可以提出行动建议，但不能自行授权执行。

**核心架构：**
- **不可变意图捕获**：Agent 提出的操作意图被不可变地记录
- **Decionis 策略引擎**：独立的安全策略判断（ALLOW / ESCALATE / BLOCK）
- **人工验证审批**：高风险操作需要人工确认后才执行
- **SafeExecutor**：消费一次性意图绑定授权，执行 Agent 建议的操作
- **MCP 兼容**：与 MCP 协议集成

**后端开发者关注点：** Agent 安全是当前最紧迫的工程问题。传统做法是 Agent 直接执行命令，但这带来了严重的安全风险。这个框架提出了"建议-审批-执行"的三层架构，是 Agent 安全领域值得参考的设计模式。

## 四、🔍 趋势洞察与深度分析

### 趋势 1：DeepSeek Harness 引爆 Agent 运行时生态（🔥 今日最大信号）

deepseek-ai/deepseek-harness 以 11.5 万星登顶 GitHub Trending，是 2026 年最火爆的开源项目之一。它代表了一个重要的趋势：

- **Agent 运行时标准化**："Everything is a Plugin" 的架构理念，将 Agent 能力完全解耦为插件，核心引擎仅负责编排
- **生态爆发速度**：3 天内催生了 10+ 个生态项目（桌面端、Web UI、TUI、插件精选等），说明社区需求极其旺盛
- **与 OpenSandbox 的路径对比**：DSH 偏"编排+前端"，OpenSandbox 偏"沙箱+安全隔离"，两者互补而非竞争

**给后端开发者的启示**：Agent 运行时正在成为独立的基础设施层。如果你在做 AI 平台，"插件化 + 编排引擎"的架构方向值得投入。DSH 的 TypeScript 生态也意味着前端开发者正在深入参与 Agent 基础设施的建设。

### 趋势 2：Agent 安全成为独立架构层

decionis/agent-safe-pipeline 的崛起说明了一个关键问题：Agent 可以提出建议，但不应该自己执行。

- **"建议-审批-执行"三层架构**：不可变意图捕获 → 独立策略引擎判断 → 人工验证 → 一次性授权执行
- **安全策略即代码**：ALLOW / ESCALATE / BLOCK 的决策逻辑可以用代码定义和版本控制
- **MCP 协议集成**：Agent 安全与工具协议（MCP）的结合正在成为标准

**给后端开发者的启示**：如果你的 Agent 系统还没有安全层，现在是时候加了。参考 agent-safe-pipeline 的架构设计，至少要在 CI/CD 中集成 Anti-slop 这样的代码质量门禁。

### 趋势 3：端侧 AI Agent 加速落地

OpenSparX/MasterAgent 和 antirez/h3.c 共同指向了同一个方向：AI 推理从云端走向端侧。

- **端侧 Agent**：MasterAgent 在 Qualcomm NPU 上实现亚 100ms 延迟，零云端依赖
- **本地推理引擎**：h3.c 以纯 C 实现 Mac 原生推理，零 Python 依赖
- **安全与隐私**：端侧推理解决了数据隐私、网络延迟、离线可用性三大痛点
