### 🟡 用 LLM 做置信度打分是个坏主意（200pt，99 评论）

> **原文**：https://rumple.github.io/blog/2026/10/20/asking-llm-for-confidence.html

一篇被低估的好文：**LLM 输出的"置信度数字"没有校准意义**。作者用气象预报员的贝叶斯框架严格论证：置信度是从信息中"算"出来的，而 LLM 的自报数字没有生成机制支撑，无法通过校准检验（calibration）。任何 Agent 设计里"问模型有多确定，低于阈值就转人工"的方案，都在依赖一个不存在的信号。

**解读：** 这篇文章应该进所有 Agent 团队的必读书单。**"LLM 置信度"是当前 Agent 工程中流行度最高、理论基础最薄弱的实践之一。** 替代方案的讨论（99 条评论）指向：自一致性采样（多次采样看一致性）、证据链长度、外部校准器——都比"问模型自己"可靠。做 Agent 降级/接管（fallback）机制的同学，今天就该审计一下自己的置信度入口。

## 五、💡 趋势洞察与深度分析

### 趋势 1：形式化验证的“LLM 时刻”——从人年到人时

Anthropic 与 Theorem 合作的 [形式化验证研究](https://www.anthropic.com/research/formal-verification) 是今天技术上最重的信号（HN 22pt 的热度严重低估了它）：**用 Claude 在 123 个真实开源库的 RISC-V 汇编层证明安全属性**——证明“程序对小于 64MB 的任意输入、任意建模的 Linux 环境下都不会触发内存安全错误或断言失败”。三个关键点：

1. **规模史无前例**：seL4 内核的验证花了 20 人年，这次是 123 个库。形式化验证从“航空电子级奢侈品”走向“可批量应用的质量保证手段”——成本从人年级压到小时级；
2. **证明过程中发现了躲过 OSS-Fuzz 万亿次模糊测试的陈年 bug**——LLM 不只是“写证明快”，是**探索证明失败路径时顺带挖出了模糊测试的盲区**；
3. **在汇编层而非源码层工作**——这意味着验证对象包括了编译器输出，“编译器信任”这个软件链最深的假设第一次被大规模绕过。

**与本周叙事的嵌套**：昨天 PHP RCE 是“AI 挖洞”，今天是“AI 证明无洞”——**AI 安全能力正在从“发现”（fuzzing/exploit）扩展到“证明”（verification）**。结合昨日 OpenAI 的“防御者窗口”和今天的 php2shell 武器化竞赛，攻防双方的工具箱都在被同一个引擎升级。对企业的影响判断：**18 个月内，“提供形式化证明”会出现在安全合规的采购清单里**——供应链安全（昨日 LiteLLM 投毒）给出的痛，正好是形式化验证的付费意愿。留给安全团队的动作：梳理哪些内部组件值得第一批“被证明”（答案通常是：解析器、协议实现、一切处理不可信输入的边界代码）。

### 趋势 2：信任基建的“双日落”——Quad9 与 eMudhra 的退出对照实验

今天 HN 的双头条构成了一组罕见的自然实验：**两个互联网地基组件，同一天退出，死法完全不同。**

- **Quad9 之死（法国）是“价值观退出”**：不是技术故障，不是被黑，而是“中立性”与“司法管辖权”不可调和时的主动撤离。它提出的问题属于政治哲学：**当裁决权是国家的而基础设施是全人类的，谁让步？** Quad9 的答案是：我走。代价由法国用户承担。
- **eMudhra 之死（全球）是“代码性退出”**：8 bits 熵的私钥从生成那刻起就是坏的，5 天除名根信任、7 天关停业务线。它提出的问题属于工程哲学：**当“信任”被编码，一行坏代码的半衰期有多长？** 答案：17 个月的暴露，加 7 天的死刑。

**并排读的结构性结论**：互联网的信任层（DNS、PKI、CA、根程序）本质上仍是 90 年代的遗产系统，正同时承受**主权压力**（Quad9）与**复杂性压力**（eMudhra）的双重挤压试验。退出本身不是终点——值得跟踪的是“退出之后”：法国的解析生态会怎样重组（评论区已在讨论 DoH 与本地缓存的行为差异）、eMudhra 的存量证书替换潮会不会暴露下一层问题（昨晚 OTP 绕过的披露暗示这家公司的问题不止密钥）。**给架构师的迁移性启示：任何“退出”（供应商、地区、协议）都应该是一次演练——你的系统里有多少组件，假设明天退出，你能在多长时间内完成替代？**
