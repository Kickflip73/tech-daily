### 1. firecrawl/anydoc — 多格式文档转 Markdown 工具（今日 ⭐1,385）

> **仓库**：https://github.com/firecrawl/anydoc
> **语言**：Rust | **协议**：Apache 2.0

**这是什么：** Firecrawl 团队开源的多格式文档转换工具，将 Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV、PDF 等格式一键转换为干净的 Markdown。

**技术架构与核心能力：**
- **Rust 原生实现**：高性能、零内存泄漏风险，适合大规模文档处理
- **多格式支持**：覆盖办公文档全谱系（Office + 开源格式 + 电子书）
- **多语言绑定**：提供 Node.js 和 Python SDK，方便集成到现有工作流
- **Markdown 输出优化**：保留文档结构（标题层级、表格、列表），去除冗余格式

**后端开发者关注点：** 文档解析是 AI Agent 工具链的基础设施。anydoc 的 Rust 方案相比传统 Python 方案（如 python-docx）性能提升显著，适合处理批量文档。如果你的 Agent 需要"读取用户上传的 Word 文档并提取内容"，anydoc 是一个标准化的入口。

### 4. disler/super-simple-software-factory — 确定性 Agent 工作流工厂（今日 ⭐351）

> **仓库**：https://github.com/disler/super-simple-software-factory
> **语言**：Python | **协议**：MIT

**这是什么：** 将 Agent + 代码工作流打包为可复用的"Skill"，一次定义，任意仓库复用。核心理念：**确定性 Python 控制流程，Agent 作为有界执行单元**。

**技术架构：**
- **Python 编排层**：确定性的 DAG 工作流定义，Agent 调用作为节点
- **有界 Agent**：Agent 被限制在预定义的任务范围内，避免"自由发挥"
- **Skill 模板化**：预置常见工作流模板（代码审查、重构、测试生成）
- **可复现性**：相同输入 → 相同输出，适合 CI/CD 集成

**后端开发者关注点：** 这是 Agent 工作流"确定性化"的尝试——用 Python 控制流替代纯 Agent 决策，提升可靠性。如果你在做 Agent 编排平台，参考其 DAG 定义和 Agent 边界设计。
